# Instructions that have an adopter edit a file an upstream merge will change

**Priority:** P2 · **Status:** open
**Found by:** the adopter-merge-friction sweep, 2026-11-16 (`fix/adopter-merge-friction`), after a first adopter's
second upstream merge hit two of them.

## The class

An adopter takes SSSB by fork and takes updates by merge (ADR-0013). Anything upstream edits, an adopter
should not edit, or every later merge conflicts there. Two cases were fixed in `fix/adopter-merge-friction`: the
path gate failing on a merged-in doc that cites `apps/starter`, and `sssb check-demo-size`'s header (`packages/tools/src/commands/check-demo-size.js`)
asking the adopter to record budget changes in it. This note lists the instructions found by the same sweep
that were NOT fixed, because each needs a decision. "SSSB-owned" means a file upstream merges touch: anything
under `packages/kit`, `scripts/`, `docs/`, `.claude/`, the root configs, `CLAUDE.md` and `README.md`.

## The largest one is gone

`init-app --eject-showcase` rewrote path citations in about 60 docs and generalized about 16 more, so adoption
manufactured a merge conflict near each on day one. `init-app` was retired in ADR-0014's P12, and a workspace
`@sssb/create` writes takes SSSB as packages rather than by merge. The rows above still apply to a repository
adopted earlier as a fork, until it switches (ADR-0014; `docs/adr/0013-upstream-updates-fork-and-merge.md` is
superseded at P15).

## What done looks like

Each row decided, and the ones that stay open moved to their own file. Nothing here is a bug in a gate: every
gate is green in an adopted tree, which is why the class only shows up at the second merge.
