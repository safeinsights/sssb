# Release notes: v0.8.0

2 changes, 1 requiring action.

## Upgrading to this release

Every release asks these of a workspace, whatever its entries say. Make them on a branch, in order, then read the
entries below.

**1. Move every `@sssb/*` package to 0.8.0, together.** In the root `package.json`, each
`apps/<app>/package.json` and `apps/<app>/infra/package.json`, and any package of your own that depends on one,
change each `@sssb/*` version, then install and commit the lockfile. First make any "Scaffold changes to apply by
hand" entry below that touches how packages install, or the install keeps the old release.

```json
{
    "@sssb/kit": "^0.8.0",
    "@sssb/tools": "^0.8.0",
    "@sssb/eslint-plugin": "^0.8.0",
    "@sssb/cdk": "^0.8.0"
}
```

```sh
pnpm install
```

**2. Refresh the app guide's copy,** the rules every agent in your repository follows. `sssb doctor` fails until the
copy is the installed kit's; read the diff of `.claude/sssb-guide.md`.

```sh
pnpm exec sssb guide
```

**3. Raise both pins to this release's commit.** The reusable workflow's `uses:` in
`.github/workflows/checks.yml` and the plugin marketplace's `ref` in `.claude/settings.json` are two pins on one commit
of SSSB's repository, and the installed `@sssb/kit` records it. This reads it there and writes both, printing each pin it
changed, and does nothing to one that is already current. It refuses, changing nothing, when the kit carries no release
stamp or a file is not the shape it edits:

```sh
pnpm exec sssb pin
```

If it refuses, make the two edits by hand: the `uses: safeinsights/sssb/.github/workflows/app-checks.yml@<commit>` line and the
marketplace's `ref`. The commit is the one `sssb doctor` names beside a pin that differs or, for a kit with no stamp, the one this prints: `git ls-remote https://github.com/safeinsights/sssb 'refs/tags/v0.8.0' 'refs/tags/v0.8.0^{}' | tail -n 1 | cut -f 1`. A pin takes the commit's SHA, never the tag `v0.8.0`, which can be moved.

Then each person updates their installed plugin and restarts Claude Code:

```sh
claude plugin marketplace update sssb
claude plugin update sssb@sssb --scope project
```

**4. Apply each entry below, then drop what it left unused.** Do each "To adopt" and delete what each "Now deletable"
describes, then run `pnpm knip`. A vendor SDK your app listed only for code you deleted (`@aws-sdk/client-s3` for a
copy of the kit's S3 storage adapter, say) is now flagged as unused, because the kit's adapter that replaces it
carries its own copy: remove it from the `package.json` that lists it, unless other code still imports it.

```sh
pnpm knip
```

**5. Check, then push.** Read every line `sssb doctor` reports, not just the last: it fails on versions out of step and
a stale guide copy, and only reports a pin that is not the release commit.

```sh
pnpm exec sssb doctor
pnpm verify
```

## Seam changes

### Sign in with an enrolled second factor

Action: required · `@sssb/kit`, `@sssb/create`

**What changed.** `RealSignInForm` (`@sssb/kit/adapters/real/sign-in-form`) now signs in a person whose account has a
second factor: after the password it asks for a code from an authenticator app, a text message, an email or a set of
backup codes, whichever the account offers, with a choice and a resend. It does the same for the provider's check of a
new device. It used to stop there with a message that it was not built. A factor it takes no code for (a passkey, an
emailed link), and any other status it does not know, gets a message that says so.
`SignInLabels` loses `mfaNotImplemented`, and the framework catalog loses `auth.mfaNotImplemented`.

**To adopt.** Delete this line from your sign-in page's `labels` (`src/app/[locale]/signin/page.tsx`); with it left in,
a page that writes the labels inline no longer typechecks, and any other logs a missing message:

```ts
mfaNotImplemented: t('mfaNotImplemented'),
```

The form reads the rest of its copy from the framework's catalog, so it
must render under `NextIntlClientProvider`, as `SignInScreen` must. Once you have tried it on your provider's development
instance (the `auth-dev` row of SSSB's cutover checklist), an operator whose provider requires a second factor can use
SSSB's form. It signs in with a factor a person already has: enrolling one still happens outside SSSB.

**Now deletable.** A sign-in form of your own written to handle a second factor or a new-device check.

## Operator actions

### Name the origins whose Clerk session tokens a deployment accepts

Action: optional · `@sssb/kit`

**What changed.** A new optional server setting, `CLERK_AUTHORIZED_PARTIES`: the app's own origins, comma-separated,
handed to Clerk's middleware as `authorizedParties`. With it set, a request whose session token was minted for another
origin, or names none, is signed out. Unset, nothing changes. A malformed value (a path, a trailing slash, upper case, a
wildcard, a duplicate, `http` other than for `localhost`, `127.0.0.1` or `[::1]`, an empty entry or an empty value)
fails every request the server answers, naming the entry, and `sssb check-real-env` reports it on cutover row
`auth-dev`.

**To adopt.** If your app shares its Clerk instance with another product, or your policy requires the check, set
`CLERK_AUTHORIZED_PARTIES` in each deployment's server environment to every origin that deployment is served from,
custom domain, CloudFront host and preview hosts included, each written as a bare origin:
`CLERK_AUTHORIZED_PARTIES=https://app.example.org,https://d1234abcd.cloudfront.net`. Then sign in and check a page
and an API route still see you signed in: a wrong list signs everyone out. SSSB's adopting reference, "How sign-in
places people", has the details.
