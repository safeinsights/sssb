# Release notes: v0.7.0

3 changes, 1 requiring action.

## Upgrading to this release

Every release asks these of a workspace, whatever its entries say. Make them on a branch, in order, then read the
entries below.

**1. Move every `@sssb/*` package to 0.7.0, together.** In the root `package.json`, each
`apps/<app>/package.json` and `apps/<app>/infra/package.json`, and any package of your own that depends on one,
change each `@sssb/*` version, then install and commit the lockfile. First make any "Scaffold changes to apply by
hand" entry below that touches how packages install, or the install keeps the old release.

```json
{
    "@sssb/kit": "^0.7.0",
    "@sssb/tools": "^0.7.0",
    "@sssb/eslint-plugin": "^0.7.0",
    "@sssb/cdk": "^0.7.0"
}
```

```sh
pnpm install
```

**2. Refresh the app guide's copy,** the rules every agent in your repository follows. `sssb doctor` fails until the
copy is the installed kit's; read the diff of `.claude/sssb-guide.md`.

```sh
pnpm exec sssb guide
```

**3. Raise both pins to this release's commit.** The reusable workflow's `uses:` in
`.github/workflows/checks.yml` and the plugin marketplace's `ref` in `.claude/settings.json` are two pins on one commit
of SSSB's repository, and the installed `@sssb/kit` records it. This reads it there and writes both, printing each pin it
changed, and does nothing to one that is already current. It refuses, changing nothing, when the kit carries no release
stamp or a file is not the shape it edits:

```sh
pnpm exec sssb pin
```

If it refuses, make the two edits by hand: the `uses: safeinsights/sssb/.github/workflows/app-checks.yml@<commit>` line and the
marketplace's `ref`. The commit is the one `sssb doctor` names beside a pin that differs or, for a kit with no stamp, the one this prints: `git ls-remote https://github.com/safeinsights/sssb 'refs/tags/v0.7.0' 'refs/tags/v0.7.0^{}' | tail -n 1 | cut -f 1`. A pin takes the commit's SHA, never the tag `v0.7.0`, which can be moved.

Then each person updates their installed plugin and restarts Claude Code:

```sh
claude plugin marketplace update sssb
claude plugin update sssb@sssb --scope project
```

**4. Apply each entry below, then drop what it left unused.** Do each "To adopt" and delete what each "Now deletable"
describes, then run `pnpm knip`. A vendor SDK your app listed only for code you deleted (`@aws-sdk/client-s3` for a
copy of the kit's S3 storage adapter, say) is now flagged as unused, because the kit's adapter that replaces it
carries its own copy: remove it from the `package.json` that lists it, unless other code still imports it.

```sh
pnpm knip
```

**5. Check, then push.** Read every line `sssb doctor` reports, not just the last: it fails on versions out of step and
a stale guide copy, and only reports a pin that is not the release commit.

```sh
pnpm exec sssb doctor
pnpm verify
```

## Operator actions

### One wait for a paused Data API cluster, and a typed error after it

Action: required · `@sssb/kit`

**What changed.** On the `data-api` transport, a request that wakes a paused Aurora Serverless v2 cluster now makes one
wait, shared by every call that waits and polled about every second, instead of a growing backoff in each call. A call
waits 18 seconds by default. A `BeginTransaction` that is throttled joins the wait; a statement is still sent again
only after `DatabaseResumingException`, and never once another statement has succeeded in its transaction. When the
wait runs out, or the Data API throttles a statement, times it out, or says the writer or the service is not available,
the error is now `DatabaseUnavailableError` (`@sssb/kit/ports/errors`), with AWS's error as its `cause`. A few answers
that the database is resuming fail at once with it, without a wait: to a commit, whose outcome is then unknown, so
never assume that it failed; to a statement after another has succeeded in its transaction; and to a statement as a
`BadRequestException`. A `pg` deployment is unchanged.

**To adopt.** On `pg`, nothing. On `data-api`, answer the error as you would a busy service; the starter's
`withPortErrors` does it (the scaffold entry of this release). Code that matched the thrown error's `name` against
`DatabaseResumingException`, `ThrottlingException`, `StatementTimeoutException`, `DatabaseUnavailableException` or
`ServiceUnavailableError` must use the typed error instead, or it stops matching:

```ts
import { DatabaseUnavailableError } from '@sssb/kit/ports/errors'

if (error instanceof DatabaseUnavailableError) {
    // error.reason: 'resuming' | 'throttled' | 'timed-out' | 'unavailable'
}
```

Repeat a read by itself if you like, and a write only when the person asks: treat a throttled or timed-out statement or
commit as if it may have run. The wait is set on the server, in milliseconds, and checked at boot; 0 fails at once.
Leave room for the rest of the request under the server's 30-second timeout. In `infra/app.ts`, with the construct kept
(`const sssbApp = new SssbApp(...)`), before `app.synth()`:

```ts
sssbApp.server.addEnvironment('DATABASE_RESUME_BUDGET_MS', '10000')
```

**Now deletable.** Code that searches an error and its causes for AWS names, or for "is resuming", to tell that the
database is waking up.

## Scaffold changes to apply by hand

### `withPortErrors` answers a database that is unavailable for now with a 503

Action: optional · `@sssb/create`

**What changed.** The starter's `src/app/api/respond.ts` maps `DatabaseUnavailableError` to a 503 with `Retry-After`,
instead of rethrowing it as a 500.

**To adopt.** In your `withPortErrors`, before the final `throw error`, importing `DatabaseUnavailableError` from
`@sssb/kit/ports/errors`:

```ts
if (error instanceof DatabaseUnavailableError) {
    console.warn(`database unavailable (${error.reason}): ${error.message}`)
    return Response.json(
        { error: 'database-unavailable', reason: error.reason },
        { status: 503, headers: { 'retry-after': String(error.retryAfterSeconds) } },
    )
}
```

## Other changes

### Avatar initials skip punctuation

Action: none · `@sssb/kit`

**What changed.** The user menu's avatar and the identity rows (the menu's header, the team switcher) took the first
character of each of the first two words of a name (the first two characters of a one-word name), punctuation
included, so `Ana (Bea) Cruz` showed `A(`. They now show the first letters of the first and last words that start with
a letter, uppercased: `AC`. A one-word name shows one letter, where it showed two. A person with no such word shows
the first letter (or digit) of their email.
